# Meeting capture: PMPS and design meeting

Everything in this folder except this README is generated by `npm run design:forms` from
`lib/designMeeting/formSpec.ts`. Edit the spec, not the files.

| Meeting | Run it from | Granola template | Granola recipe | Paper worksheet |
|---|---|---|---|---|
| Peace of Mind Planning Session | `pmps-checklist.md` | `pmps-granola-template.md` | `pmps-granola-recipe.md` | `pmps-worksheet.docx` |
| Design meeting | `checklist.md` | `granola-template.md` | `granola-recipe.md` | `design-meeting-worksheet.docx` |

## How a meeting reaches the design sheet

1. Take the note with the meeting's **Granola template**, or fill in the worksheet.
2. Run the meeting's **Granola recipe** on the note. It returns a *Design sheet recap* in the
   exact labels and option tokens the importer accepts, a *Missing information* list, and a
   *Follow-up tasks* checklist.
3. On `/admin/drafting/<matterId>`, open **Complete sheet** and either paste the recap (only the
   part above *Missing information*) into **Paste notes**, or upload the worksheet through
   **Word document**. A PMPS note attached to the lead with **Add meeting notes** is also read
   by **Fill what is missing** once the matter is hired. Review and accept.
4. In the same dialog, press **Create follow-up task**. It reads what the sheet still lacks
   from the readiness engine and puts it on the matter as one checklist task, split into
   *Ask client*, *Needed* and *Attorney sign-off*. Pressing it again refreshes the same task:
   answered items tick themselves off, new gaps are appended.

## Gaps: what the meetings capture that the design sheet cannot hold

The import only writes fields in the design-sheet registry. These answers are asked for at the
table but have no field, so today they land in drafting notes (or nowhere) and someone has to
carry them by hand.

| Captured at | Answer | Where it goes today | Why it matters |
|---|---|---|---|
| PMPS | Legal plan, member ID, fee quoted, optional services | Entered by hand on the matter's **Billing** tab (the import leaves them in drafting notes) | The PMPS package reads them from the matter, but nothing carries them there from the meeting note |
| PMPS | Child from a prior relationship, special needs, deceased child with descendants | Drafting notes | Each changes the plan; the PMPS preflight flags them as non-schema |
| PMPS | Mortgage balance, values per spouse vs combined, prior taxable gifts, anticipated inheritance | Asset notes / drafting notes | Each moves the Massachusetts estate-tax figure |
| PMPS | First name each client goes by | Nowhere | Used in the proposal's salutation |
| PMPS | Discretionary standard (HEMS, college), contingent chain, asset-protection wishes | Drafting notes | The proposal's Key Trust Provisions render boilerplate unless these reach the trust document's description |
