# Billing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an authenticated, persistent `/admin/billing` workspace for engagement revenue, receivables, payments, legal-plan claims, aging, and weekly billing follow-up.

**Architecture:** Store billing items, payments, immutable billing events, and per-user nudge dismissals in Supabase. Seed one engagement billing item idempotently when a matter becomes signed, while preserving the existing engagement workflow. Keep financial mutations behind authenticated admin routes that call atomic, actor-checked database functions; load the page on the server and derive presentation metrics in tested TypeScript helpers.

**Tech Stack:** Next.js App Router, React 19, TypeScript, Supabase/Postgres, shadcn/ui and Radix, Tailwind semantic tokens, Vitest and Testing Library.

## Global Constraints

- Reuse existing components and patterns before creating new ones.
- Use the existing shadcn/ui and Radix primitives; add no component or styling library.
- Use semantic theme tokens, with light and dark theme support.
- Reuse `AdminPageShell`, `PageHeader`, `SearchField`, `FilterChip`, `Card`, `Table`, `Dialog`, `Select`, `Progress`, `Badge`, and `EmptyState`.
- Preserve attorney/admin authorization, existing engagement persistence, and auditable workflow behavior.
- Do not modify drafting internals.
- Treat mobile responsiveness, keyboard access, focus management, accessible names, and screen-reader semantics as release requirements.
- Store money as integer cents in the billing tables. Existing `matter_details.flat_fee_amount` values are dollar amounts and are converted exactly once during engagement seeding.
- Treat overdue as a derived flag, never a stored status.
- Use `61+` for the final aging bucket because the prototype puts every balance older than 60 days in its third bucket; this prevents balances older than 90 days from disappearing.
- Claim-prep links target the existing Library search surface. This task does not invent legal-plan claim documents or modify drafting workflows.
